# 設計書点検ツール群

設計書・ドキュメントのレビューを支援する、汎用チェックツール集です。

## 目的

- 設計書レビューの品質を均一化する
- レビュー前の機械チェックで初期不備を排除する
- チェック観点を標準化し、再利用可能にする
- 設計書間の整合性チェックを容易にする

## 基本方針

チェック観点ごとにツールを分割し、シンプル・保守しやすい構成を保つ。
PythonとAIの役割を明確に分担する。

| 分類 | 担当 | 例 |
|------|------|----|
| 機械的に判定できるチェック | Python | 必須項目未入力、重複、命名規約、表記揺れ、設計書間突合 |
| 意味理解が必要なチェック | AI | 説明不足、曖昧表現、観点漏れ、設計意図の不整合 |

## チェックツール一覧

番号はチェックを実施する推奨順序を示す（構造確認 → 値確認 → 文字確認 → 内容確認 → 実態突合 → AI確認）。

| フォルダ | チェック観点 | スクリプト | 担当 |
|----------|-------------|-----------|------|
| `01_format_フォーマット確認/` | フォーマット準拠（テンプレート構造） | `check_format.py` | Python |
| `02_required_必須項目確認/` | 必須項目の未入力・空欄検出 | - | Python |
| `03_charset_文字種確認/` | 文字種チェック（全角/半角混在等） | - | Python |
| `04_notation_表記揺れ確認/` | 表記揺れ・用語統一 | `check_notation.py` | Python |
| `05_naming_命名規約確認/` | 命名規約違反の検出 | `check_naming.py` | Python |
| `06_duplicate_重複確認/` | 重複定義・重複記述の検出 | `check_duplicate.py` | Python |
| `07_consistency_整合性確認/` | 設計書間の整合性チェック | - | Python |
| `08_existence_実態突合確認/` | 実態との突合チェック（設計書記載 vs 実ファイル等） | `check_existence.py`（軸ファイル方式） | Python |
| `09_ai_review_AIレビュー/` | AIによる品質レビュー | - | AI（Claude API等）|

### 01_format_フォーマット確認 の担当範囲について

`01_format_フォーマット確認` は**テンプレート定義（YAML）との構造的な一致**のみを確認する前提チェック。
01がNGの場合、後続のチェックは正しく機能しない可能性があるため、最初に実施する。

| チェック内容 | 01の担当 | 担当ツール |
|------------|:-------:|----------|
| 定義したシートが存在するか | ✅ | 01 |
| 定義した列ヘッダーが存在するか | ✅ | 01 |
| 特定セルに何か値があるか（有無のみ） | ✅ | 01 |
| 必須項目のセルが全て埋まっているか（値の充足） | ❌ | 02 |
| 列名・シート名が命名規約に沿っているか | ❌ | 05 |
| ヘッダーに全角/半角の混在がないか | ❌ | 03 |

> **判断基準**：「テンプレートに定義した期待値との突合」は01、「値の品質・ルール適合」は後続ツールに委ねる。

### 04_notation_表記揺れ確認 の仕様

`notation_rules.yaml` に正規表記（correct）と揺れ語リスト（variants）を定義し、CSVの指定列をチェックする。

| モード | 説明 |
|--------|------|
| 完全一致（デフォルト） | セル値全体が揺れ語に一致するか判定 |
| 部分一致（`--partial`） | 正規表記を除去した残りのテキストに揺れ語が含まれるか判定。「ユーザー」を除去後に「ユーザ」があれば検出 |

- `--cols` で対象列を限定可能。省略時は全列チェック
- `--case-sensitive` を付けると大文字/小文字を区別する

### 05_naming_命名規約確認 の仕様

`naming_rules.yaml` に列ごとのルール（正規表現・最大文字数・禁止語）を定義し、CSVの対象列の値を検証する。

| チェック項目 | 説明 |
|------------|------|
| パターン不一致 | `pattern`（正規表現）に一致しない値を検出 |
| 文字数超過 | `max_length` を超える値を検出 |
| 禁止語あり | `forbidden_words` に含まれる語（大小文字区別なし）を検出 |
| 必須値なし | `allow_empty: false` の列で空値を検出 |

- ルールファイルにCSVに存在しない列名を指定した場合はスキップして警告表示
- 1つのYAMLに複数列のルールを定義できる（テーブル名・カラム名・画面IDなど）

## ユーティリティツール一覧

チェックの前処理・補助に使う汎用ツール。

| フォルダ | 概要 | スクリプト | 担当 |
|----------|------|-----------|------|
| `00_utils/file_list_ファイル一覧/` | フォルダ配下のファイルを一覧化（CSV出力） | `file_list.py` / `file_list_batch.py` | Python |
| `00_utils/excel_extract_Excel抽出/` | Excelの指定シートからデータ行を抽出・マージ（CSV出力） | `excel_extract.py` | Python |
| `00_utils/keyword_search_キーワード検索/` | キーワードを含むファイル・行を一覧表示（テキスト/Excel/Word対応） | `keyword_search.py` | Python |
| `00_utils/md_merge_MD結合/` | フォルダ配下の Markdown ファイルを1つに結合（ファイル名見出し付き） | `md_merge.py` | Python |

## CSV中継フォルダ（csv/）

ツール間でCSVファイルを受け渡す際の共通フォルダ。

```
csv/
├── file_list.csv                  ← file_list.py の出力
├── excel_extract_result.csv       ← excel_extract.py の出力
├── check_duplicate_result.csv     ← check_duplicate.py の出力（例）
└── check_existence_result.csv     ← check_existence.py の出力（例）
```

- 各BATファイルのデフォルト出力先はこのフォルダに設定済み
- `.gitignore` により `csv/*.csv` はコミット対象外（中間ファイルを汚染しない）
- フォルダ自体は `.gitkeep` でリポジトリ管理（クローン直後から利用可能）
