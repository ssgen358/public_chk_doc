# 設計書点検ツールの構想整理

## 1. 背景

設計書や各種ドキュメントのレビューを実施する際、以下の課題がある。

- 設計書ごとにチェック手順を毎回考える必要がある
- 同じ観点のチェックを繰り返し作っている
- 人手レビューでは、形式的なミスの見逃しが発生する
- 設計書の種類（画面、IF、バッチ等）が多く、標準化が難しい

そこで、**設計書点検をある程度自動化する汎用ツール群を整備する**。

目的は次の通り。

- 設計書レビューの品質を均一化する
- レビュー前に機械チェックで初期不備を排除する
- チェック観点を標準化し、再利用可能にする
- 設計書間の整合性チェックを容易にする

---

## 2. 基本方針

### 2.1 観点ごとにツールを分割する

すべてのチェックを1つのツールにまとめるのではなく、
**チェック観点ごとにツールを分割する。**

理由
- ツールがシンプルになる
- 保守しやすい
- 観点追加が容易
- チェック結果が理解しやすい

### 2.2 PythonとAIの役割分担

チェック内容により、PythonとAIを使い分ける。

#### Python向き

機械的に判定できるもの

- 必須項目未入力
- 重複
- 命名規約違反
- 表記揺れ
- 文字種（全角/半角混在）
- 設計書間の突合

特徴
- 再現性が高い
- 処理が高速
- 自動化しやすい

#### AI向き

意味理解が必要なもの

- 説明不足
- 曖昧表現
- 観点漏れ
- 設計意図の不整合

特徴
- 柔軟なレビュー
- 文書レビュー補助

---

## 3. ツール構成

### 3.1 チェックツール

番号はチェックを実施する推奨順序を示す（構造確認 → 値確認 → 文字確認 → 内容確認 → 実態突合 → AI確認）。
各ツールは独立したフォルダに配置する。

| フォルダ | チェック観点 | 担当 |
|----------|-------------|------|
| `01_check_format/` | フォーマット準拠（テンプレート構造） | Python |
| `02_check_required/` | 必須項目の未入力・空欄検出 | Python |
| `03_check_charset/` | 文字種チェック（全角/半角混在等） | Python |
| `04_check_notation/` | 表記揺れ・用語統一 | Python |
| `05_check_naming/` | 命名規約違反の検出 | Python |
| `06_check_duplicate/` | 重複定義・重複記述の検出 | Python |
| `07_check_consistency/` | 設計書間の整合性チェック | Python |
| `08_check_existence/` | 実態との突合チェック（設計書記載 vs 実ファイル等） | Python |
| `09_check_ai_review/` | AIによる品質レビュー | AI（Claude API等）|

**各観点の補足**

- `01_check_format`: テンプレートのシート名・列名・セル位置が規定通りか確認する。他のチェックが正しく動作するための前提となる。
- `03_check_charset`: 全角/半角の混在、機種依存文字の使用を検出する。表記揺れとは独立した観点。
- `04_check_notation`: 同一概念に複数の表現が使われていないか（用語辞書との照合を含む）。
- `05_check_naming`: 項目名・変数名等の識別子が命名規約に従っているか。
- `07_check_consistency`: 複数の設計書をまたいだ整合性（例：IF設計書に記載のファイル名がバッチ設計書と一致しているか等）。**設計書間**の突合。
- `08_check_existence`: 設計書に記載された成果物（ファイル名・テーブル名等）が**実際に存在するか**の突合。SVN等のリポジトリやフォルダ上の実ファイルと照合する。07との違いは「ドキュメント同士」ではなく「ドキュメントとシステム実態」の突合である点。

### 3.2 ユーティリティツール

チェックの前処理・補助に使う汎用ツール。チェックツールとは分離して `00_utils/` 配下に配置する。

| フォルダ | 概要 | 担当 |
|----------|------|------|
| `00_utils/file_list/` | フォルダ配下のファイルを一覧化（CSV出力） | Python |

**file_list の用途例**

- 設計書に記載されているファイル名が実際に存在するかの突合元データを作成する
- 対象フォルダのファイル構成を把握する

---

## 4. 今後の拡張方針

- 対象ファイル形式はExcel・Word・CSVを基本とする
- チェック観点は順次追加していく
- チェック結果の出力形式は統一し、CSVレポートとして出力できるようにする
- ユーティリティツールで出力した一覧をチェックツールのインプットとして活用する
